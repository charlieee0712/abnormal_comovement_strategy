## 1. 仪器教训（工具 / 运行层；都已在当时修正，产物未受影响）

1. **pyarrow 起 S3 线程**：pyarrow 13 在 import 时初始化 S3，起约 192 个 AwsEventLoop 线程（E6g / E6h 登记为 I7"来源未查明"的约 205 线程 / 进程）。`e6i_boot.py` 在所有入口第一行预置 `sys.modules['pyarrow._s3fs'] = None` 并把 BLAS 线程设为 4 → 13 线程 / 进程。VERIFY 的只读程序照抄这两行（不 import 本轮模块）。
2. **npz 整块重读 → 约 684 GB**：`np.load` 返回的 NpzFile 每次 `z[key]` 都把整块数组重新解压，行视图又留住整块；`e6i_vs_h5.py` 首版逐描述符取行，RSS 升到约 684 GB（机器 2.2 TB）。按 PID + 启动时间停掉，改为每个 npz 只读一次、逐行 copy 后重跑。
3. **`~False = −1`**：FOCAL new 臂的掩码 `base & ~(… else False)` 在分支取到 Python `False` 时变成 `& −1`，掩码变整数，配额按全部单元计数（shortfall 185,737）。selftest 抓到；改为显式分支 + dtype 断言。
4. **`pkill -f` 误杀**：一次用 `pkill -f <命令行模式>` 清理 selftest，模式同时匹配到执行该命令的远程 shell，ssh 会话被杀（exit 255），未影响产物。此后只按 PID + 启动时间 + 完整命令行清理（协议 §10）。
5. **Z-MAP 路径数按 H 重复计**：路径按 (配置, 机制) 抽取、同一配置的各 H 共用；按 (描述符, 机制) 行把 n_paths 相加得到 25.59M（约 4 倍），按配置计为 6.58M（2010-14 2.89M / 2015-18 3.70M）。交付前更正。
6. **本地 shell 没有 python**：本地 Git Bash 里的 `python - <<EOF` 静默不执行，一次改脚本没生效；远端核对时才发现。本地改文件一律用编辑工具，改后在远端核对内容。
7. **shell 替换写进真换行**：用 `sed` 往 Python 源里写 `\n`，写成了真换行，字符串字面量断开；上传后先 `ast.parse` 才运行的检查拦住。
8. **命令落在本地而不是 47**：`ssh 47 'python3 -' <<EOF … EOF` 之后的下一行命令在本地执行（报"找不到文件"）。多条远端命令放进同一个 ssh 字符串。

### 8.4 独立性的范围（事实）

1. 为转录汇总口径（主方向集合、伴随账户正则、各表的分组 / 过滤 / 格式串），V 阶段读了 e6i 报告生成器与统计脚本的**源码文本**（没有 import、没有执行）；这不在 brief §1 的封闭输入清单里。因此 V 能抓到计算与转录错误，抓不到"生成器口径本身写错"——D2 的句子是按生成器公式重建的。
2. V 的数值全部来自日账本、存档表与钉住引擎重放；没有读 `cache/`，没有读 E7 数据文件，没有 import e6i 模块（每个阶段结束自检 `sys.modules`）；钉住引擎重放期间其影子缓存目录没有新增或改动文件。
3. 进入 V 的闭包门（01:52:14）PASS；此后全链重跑时闭包门记 FAIL，唯一原因是 C-2 写进 47 `exec_briefs/` 的 `E6i_MIRROR.md5` 在提交前是 untracked。

### 8.5 对协议 / brief 模板的建议（流程层）

1. brief 的预期计数与容差由脚本从产物现算后写入（附出处），不从 REPORT 印出值转抄。
2. 报告生成器写 query_ids 时检查跨文件唯一性；正文之外的事实块在 REVIEW_input 里标注所在文件。
3. 含随机性的对照臂使用与进程无关的种子，并把种子写进账本元数据。
4. brief §1 写明"生成器源码可读、不可执行"，或让 REPORT 表头附带分组 / 过滤口径，使 V 不必读源码。
