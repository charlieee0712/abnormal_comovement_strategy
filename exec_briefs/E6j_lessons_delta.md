# E6j lessons_delta（执行端；不写共享 memory，交付时随 REPORT 一次性交回）

用途：本轮执行端自己踩到的判断与教训增量，按复盘台账六类根因（A 仪器 / B 未匹配比较 / C 机制未读源码 / D 前提外推 / E 过早收口 / F 节奏文档）标注；只记事实与改法，不写推荐。

## Stage 0

1. **（F）锚 1 首跑 30 项 FAIL 全是检查定义错**（2026-09-27 00:53）：① summary 逐列数值比对用 `read_csv` 默认快速浮点解析，产生 1e−16 级假差（同一文件逐字节比对已 PASS）；② 8bp 年化用 brief 的近似式 `net6 − 0.02·turn` 配 0.005 容差，未计入"换手按账本全部 L 行年化、净值按 n 个非缺失日年化"的定义差（误差 = 0.02·turn·(L/n − 1)，近段最大 0.025）；③ 对 brief 两位小数换算值设了门。改法：对 brief 的"≈"先推精确恒等式并对它设门，近似式与文档值只记 DIFFERS / INFO；数值比对用 `float_precision='round_trip'` 或逐字节。已在 `--rerun` 修正（生产口径零改动）。
2. **（F）锚 2 汇总列把布尔检查计成数值**：`parent_identity_map.csv` 的 L4_max_abs 取了含"日期轴相同 = True"的 got 列最大值 → 1.0（真实 2.2e−16）。改法：层汇总按 metric 过滤只取数值层；`--rerun` 另出 `parent_identity_map_rerun.csv`，原件不覆盖。附带：rerun 回执的 outputs 列了根目录原件而漏列 rerun 版 map（记录，不影响正确性）。
3. **（B，观察）W03 的"同源不同路径"暂判来自两处未匹配比较**：持仓 / 资金用了两种平均口径（E5a 只在有持仓日平均 vs E6i 全日平均），8bp 净值一侧用了近似换算；账本层四层对照（锚 2）给出 exact_alias。改法（执行端侧）：身份判断只在掩码 / 权重 / 持仓 / 日账本层做，展示口径并排印两种定义。
5. **（F）等待循环 `while pgrep -f '<模式>'` 放在 `bash -c` 里会匹配到自身命令行、永不退出**（种子重放时两次）：改成按显式 PID `kill -0` 等待；47 上还有更早轮次遗留的同类休眠循环（未动，报用户）。
6. **（F）合成检验 F12 首跑 FAIL 是检验构造错**（找"下一次触发"时漏看末 5 行），改的是检验不是实现；首跑的 synthetic.csv 被重跑覆盖——此后检查产物一律带 attempt 后缀，原件不覆盖。
7. **（F）P 政策脚本的 dryrun 在 P 包封存前由程序读了 P 原生账户**（目的是在随机参照完成前先查代码错误；输出另放 `results_P/dryrun/`，本人只看了结构计数与"主母体别名 vs E6i 同描述符"的差值量级，未看政策读数）。改法：dryrun 应只用合成或无新增批次的数据；此后 P 读数一律在 `registration/seal_P.json` 之后。
8. **（F）两次 profile 启动命令的 shell 引号错误各多拉起一个进程**：均按 PID + 启动时间 + 命令行核对后结束；此后远端启动命令一律单引号包裹、先写队列文件再由 xargs 读。
9. **（观察）B 随机的主要耗时在 EDIT-ENTRY 每次重算旧 K 三档**（只依赖旧 K 与合法域）：提到循环外后单掩码约 0.05–0.08 秒；同一改动给 P 随机队列中尚未开始的任务（结果逐位不变，回执里的代码 sha 前后不同）。
4. **（C，观察）"逆向秩"的两种写法差一个常数 1/n**：E6i 源 `pct_dense_dir('lo') = (−s).rank(pct=True)`，不是 1 − pct；P 块 SRC 坐标照源式，锚 3 T6 与 E6i NSlo 表逐位。

## Stage 1 之后（运行与读数前）

10. **（F）记录 B 草稿先于 part1 落盘**：次序与 brief 的"part1 → 记录 B"相反；草稿只含冻结对象清单与条件，不含读数，A1-auto 与条件回执在 part1 之后，结论未受影响。改法：按 brief 的文件次序写，草稿也不提前。
11. **（F）P 随机队列（96 任务，实际约 16 小时）启动前没有先向用户报时间与资源**（规则：> 30 分钟先报），且预估 10 小时偏低：负载下每机制每 1,024 路径 22–35 分钟，EDIT 类最慢。改法：长队列先用 profile 实测负载下的单机制耗时再报；报告里写清 wall-clock 与并发。
12. **（C）政策判定的三处逻辑缺陷在读数前发现并改正**：MC_UNRESOLVED 写成无条件前置门（缺随机时全部对象"不可判"）、市值 gap 的 NaN 被当 FAIL（plan §4.5 L311 写明无编辑日为 NA 而非 0）、FULL / G4 结论不同未标 `POLICY_INTERPRETATION_PENDING`（plan L290）；另把"MC 误差影响符号"按 plan §8.1 L634 改为与 MCSE 是否 ≤ .03 无关。根因是写判定函数时没有逐句对照 plan 原文。改法：政策代码的每个分支注明 plan 行号；执行口径另起 `registration/policy_P_operational_addendum.json`（05:23:31，P 封存与读数之前）。
13. **（F）差点往已登记 sha 的 Stage 0 文档追加内容**：`source_resolution.md` 的 sha256 记在 `source_manifest.json`，追加会改变冻结 hash；写之前 grep 各清单发现，改为新文件 `source_resolution_addendum_policy_mc.md`。改法：改任何 Stage 0 / 登记产物前先查它是否被清单记 hash。
14. **（F）远端 `cd … && nohup setsid sh … &` 使本地 ssh 挂起**：`&` 作用于整个 `&&` 列表，后台 subshell 占着 ssh 通道；链本身已 setsid + nohup、不受影响。改法：远端长链用 `ssh -f` 或把整条命令包进 `nohup setsid sh -c '…' > log 2>&1 < /dev/null &`。
15. **（观察）后段真实差不只在账户与随机里**：P / B 诊断（CS、TRANSPORT、编辑账本、影子库存）同样含后段读数，封存范围扩到 `diagnostics/P`（四段）与 `diagnostics/B`（两后段），读取前一并核对。
17. **（E）开跑前没有做分段计时就按 brief 默认并发开了长队列**：P 随机约 16 小时、B 随机按原代码与 24 并发约 39 小时（我原报 1–1.5 天，偏乐观）。用户追问后才实测：同一路径的置换在三个 α / 六个组合里重复计算、A4b 第二关把 64 条路径拼成数千万元素做全局 lexsort、EDIT 每路径重做与路径无关的分组；而 47 的 node1 只用了 1/8 的核。改法：长队列开跑前先做分段计时（哪一段占比多少、哪些量与路径无关），把"与路径无关的先算、同一随机量只抽一次"列为随机层的默认写法；并发按实测资源向用户提议，不只沿用 brief 的起步值。提速件逐位等价测试与修订记录见 `registration/code_amendment_20260927_fast.json`。
